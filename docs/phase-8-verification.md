# Phase 8 — Today and cooking

Today selects all meal slots using an injected calendar and date, including midnight/time-zone tests. The screen re-evaluates the current date while open. Empty and cooked states are explicit. Cooking follows the selected saved recipe with scaled ingredient quantities, exact later-meal reservation notes, persistent step checks, close/resume and an optional user-set reminder timer.

Confirmed completion appends one immutable recipe/portion/date record and validates cumulative consumption against recorded purchased quantities. Planned packages do not count as actual stock. Completion without sufficient purchases is blocked. An expected revision rejects stale confirmations; repeated completion is idempotent. Purchased spending and stock history remain intact. Later household/diet settings affect uncooked meals, while cooked meals retain their recipe, date and portion profile. Cooked meals cannot be swapped, moved or removed by regeneration/settings.

Timer state is a saved absolute deadline, not a foreground counter. Expired timers remain visible until cleared, and completion clears a saved timer. No notification permission is requested. Timer changes and step updates check recipe identity, so stale cooking screens cannot change a replacement recipe's progress.

“I didn’t cook this” previews an exchange of cooking dates with another uncooked meal in the same slot. Every planned slot is already occupied; this behavior is stated before selection. The preview shows proposed dates and recalculated save-for-later amounts, then applies the same revision-checked acceptance as swaps. Cancelling consumes nothing. Storage uncertainty and package guidance are shown; no expiry duration or safety guarantee is invented from development data.
